# Loom v3: build your own computer

Loom remains unreleased. Only the current project format is supported; no migrations are implemented.

## Using the course

Open **Learn → Start course**. Each exercise has its own saved draft within the course project. Complete its interface using the permitted primitives and your previously verified components, then choose **Check circuit**. Checks run separately from the live simulation and use application-owned cases, not editable project tests.

The 20 exercises cover NAND, NOT, AND/OR, XOR, one-bit selection, eight-bit bus selection, hexadecimal segment decoding, half/full adders, eight-bit addition, subtraction, register control, accumulation, program counter, instruction fields, ALU, instruction control, CPU wiring, memory/I/O decoding, and calculator integration. Registers, memory and peripherals are provided primitives; combinational operations in course references are actual NAND logic.

The hexadecimal decoder lesson follows eight-bit bus selection. Its `value` input is four bits and `segments` output is eight bits. Connect bits 0–6 to a–g and keep bit 7 off. After checking, **Try in counter** opens a separate sandbox with your accepted implementation. The calculator remains the final exercise.

A passing check saves an immutable component snapshot and enables **Continue**. Later exercises can use that component without consulting the library catalog. Editing an earlier draft does not change snapshots already used elsewhere. Select an instance and use **Replace with verified component** to adopt a newer compatible solution explicitly, then check the affected exercise again.

Position, wire layout, names and root input-switch changes preserve electrical completion. Topology, widths, constants, parameters, initial state, ROM and dependency changes require a new check. A `width` parameter on a gate, mux or arithmetic solution is checked over every declared width; passing only the default width is insufficient. The eight-bit selector exercise also verifies explicit bus widening through eight instances of the learner's one-bit selector.

On a failed behavioral check, inspect the failing inputs, cycle, signal and expected/actual values. **Inspect failure** opens the existing isolated debugger. **Return to circuit** returns to the retained live simulation. A result from an older electrical revision cannot award completion or overwrite newer edits.

Hints are authored in three levels. **Inspect reference** opens a separate read-only project; it cannot award credit. **Return to course** restores the learner's draft. **Open sandbox** creates an unrestricted project; return to the saved course through Projects.

Imports and recovery copies reverify completion claims before enabling dependent exercises. Ordinary local-save recovery and single-writer locks remain in use. Export the complete course as a normal `.loom.json` project for an independent copy. Runtime history remains session-only.

## Calculator and CPU contract

The course retains the Loom 8 ISA and two-phase clock behavior. CPU storage slots keep the supplied IDs used by debugging and checks. Instruction checks compare PC, accumulator, flags, output and halt after each instruction. The final calculator uses the supplied assembly program on the learner's actual circuit, with keyboard input and terminal output. No instruction emulator or browser arithmetic supplies its answer.

The calculator checks include `12+34 → 46`, `255+255 → 510`, `0-255 → -255`, invalid operands/operators, and recovery on the following valid line. Disconnected adder or qualified-read paths cannot pass.

## 中文

在 **学习 → 开始课程** 中创建课程工程。20 个练习从 NAND、组合逻辑与总线开始，逐步完成算术、寄存器控制、程序计数器、指令译码、CPU 和外设，最终运行计算器。每个练习在同一工程中保存独立草稿。

**检查电路** 使用应用内置的行为检查，不会修改当前运行状态。通过后保存不可变的元件副本，并解锁后续练习。修改旧草稿不会自动改变其他练习已经采用的副本；选中实例后可明确替换为新的验证结果，再重新检查。

移动、布线外观和重命名不影响完成状态；改变连接、位宽、参数、常量、ROM 或依赖需要重新检查。声明了 `width` 参数的逻辑或算术元件必须通过范围内所有位宽的检查。8 位选择器练习还要求验证由单比特元件组合的总线行为。

失败信息包含输入、周期、信号和预期/实际值。**检查失败** 打开独立调试运行，**返回电路** 恢复原运行。三个层级的提示逐步提供帮助。参考电路只读，不会授予课程进度。

**打开自由工程** 可随时使用完整工作台；之后从“工程”返回课程。导入或恢复的课程需要重新验证完成记录。课程可作为普通 `.loom.json` 文件导出；运行历史不写入文件。

## Developer entry points

- `src/course/registry.ts`: ordered bilingual exercises, compliant references, interface/behavior checks.
- `src/course/session.ts`: drafts, normalized electrical hashes, accepted snapshots and explicit dependency replacement.
- `src/course/check.ts`: shared browser-worker/CLI course verifier and imported-record revalidation.

`loom course-check project.loom.json --json` emits deterministic course results and returns 0 only when the reverified claims and active exercise pass. Statuses are `blocked`, `invalid`, `failed`, `passed`, and `limit`.

`npm run fixture:course` generates a reference-derived QA submission fixture. It wires earlier accepted NAND-based components into later submissions. It is a testing tool, not an application completion shortcut or evidence of human authorship.
