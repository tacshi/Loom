# Loom v3: build your own computer

Loom remains unreleased. Only the current project format is supported; no migrations are implemented.

## Using the course

See [Learning and visual tests](LEARNING.md) for the current 23-lesson progression, Explore/Practice/Challenge stages, visual checkpoints, and debugging controls.

The course starts with signals, AND and NOT, then asks learners to build NAND from AND followed by NOT. Later NAND-based lessons can reuse this verified component. Verification permits its internals only when the approved dependency identity and electrical content match; arbitrary nested forbidden gates remain invalid.

Each lesson retains its independent draft. Practice uses a separately saved circuit; demonstrations never change either draft. Run tests verifies application-owned cases. Only the independent challenge can earn an immutable accepted snapshot. Names and layout preserve electrical identity; topology, parameters, constants and dependency changes require another check. Declared width variants are still checked.

The current course format records `curriculum: 2`, stage choices, and optional practice roots. Old course formats are rejected; no migrations or compatibility adapters are supplied. Import revalidates completion claims against current checks. Playback history is transient and does not enter project files.

## Calculator and CPU contract

The course retains the Loom 8 ISA and two-phase clock behavior. CPU storage slots keep the supplied IDs used by debugging and checks. Instruction checks compare PC, accumulator, flags, output and halt after each instruction. The final calculator uses the supplied assembly program on the learner's actual circuit, with keyboard input and terminal output. No instruction emulator or browser arithmetic supplies its answer.

The calculator checks include `12+34 → 46`, `255+255 → 510`, `0-255 → -255`, invalid operands/operators, and recovery on the following valid line. Disconnected adder or qualified-read paths cannot pass.

## Developer entry points

- `src/course/registry.ts`: ordered bilingual exercises, compliant references, interface/behavior checks.
- `src/course/session.ts`: drafts, normalized electrical hashes, accepted snapshots and explicit dependency replacement.
- `src/course/check.ts`: shared browser-worker/CLI course verifier and imported-record revalidation.

`loom course-check project.loom.json --json` emits deterministic course results and returns 0 only when the reverified claims and active exercise pass. Statuses are `blocked`, `invalid`, `failed`, `passed`, and `limit`.

`bun run fixture:course` generates a reference-derived QA submission fixture. It wires earlier accepted NAND-based components into later submissions. It is a testing tool, not an application completion shortcut or evidence of human authorship.
